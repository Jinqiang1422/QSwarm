## 二、架构与数据流

```
用户指令 ──► SwarmAIAgent（LLM function calling，17 工具）
                 │
                 ├─ 执行类工具 ──► SwarmManager.parseAndValidate（schema + 越界 + 语义校验）
                 │                      │
                 │                      ▼
                 │              SwarmAIAgent._queueOrExecute
                 │                      │  ① checkConstraints ──► SwarmConstraintChecker
                 │                      │       error>0 ⇒ 强制挂起人工确认（L3 也不豁免）
                 │                      │  ② estimatePlan ──► SwarmRehearsalEstimator
                 │                      │       时长/里程/最低电量裕度随计划摘要展示
                 │                      ▼
                 │              L1/L2/L3 自主分级判定（P1）
                 │                      ▼
                 │              executeActions ──► plan_coverage(assign=auction)
                 │                      │           └─► SwarmTaskAllocator 拍卖分配条带
                 │                      ▼
                 │              各 Vehicle（统一任务管线，与人工规划同一套）
                 │
                 └─ propose_candidates ──► 2~3 候选本地校验/估算
                                            ▼
                                    QML 对比卡片（优/劣/违例/预演）
                                            ▼
                                    selectCandidate ⇒ 回到正常确认管线
```

## 三、各工作包细节

### WP2.1 约束校验引擎

**新文件**：`src/Swarm/SwarmTypes.h`、`SwarmConstraintChecker.h/.cc`

- **SwarmTypes.h**（QtCore-only）：`VehicleState`（id/经纬度/相对高度/电量/在线）+ 地理工具函数
  - `haversineM`（R=6371000）、`latLonToLocalM`（等距圆柱近似）、`destinationPoint`（球面推算）、`pointInPolygon`（射线法）
- **检查规则**（违例带 severity/rule/message/suggestion 四元组）：

| 规则 | 触发 | 级别 |
|---|---|---|
| 高度上限 | takeoff 海拔 > max_altitude_m | error |
| 允许空域 | 作业区中心不在任一 include 多边形内 | error |
| 禁飞区 | 作业区中心或四角探针点落入 exclude 多边形 | error |
| 电量不足 | 估算需电 > 最低电量×reserve_factor | error |
| 电量裕度 | 需电 > 可用×85% | warning |
| 链路覆盖 | 最远作业点 > 1.5×comm_range / > comm_range | error / warning |
| 编队间距 | spacing < min_separation / < 2×min_separation | error / warning |
| 多区重叠 | 两作业区中心距 < 50 m | warning |
| 模板适配 | 在线数 < min_fleet | error（checkTemplate） |
| 载荷未知 | 模板要求载荷但机队载荷能力未知 | warning |

- **电量模型**：`bands=⌈width/spacing⌉`，`sweep=bands×length+(bands−1)×spacing`；`perVehicleM=sweep/nV+maxTransit`；`missionMin=perVehicleM/cruise+2×alt/climb`；`needed=missionMin/endurance×100`
- **配置**：`AppDataLocation/SwarmConfig/fences.json`，首次运行写默认（include/exclude 多边形、高度上限、链路半径、巡航速度、爬升率、续航、余量系数、最小间距）；`fenceSummary()` 面板实时可见
- **闸门语义**：`_queueOrExecute` 中 error 级违例 ⇒ 强制 pending 人工确认，**L3 白名单不豁免**；warning 仅提示不阻断；全部违例写审计 `safety/constraint_check`

### WP2.7 解析式仿真预演

**新文件**：`SwarmRehearsalEstimator.h/.cc`

逐动作累计：takeoff=alt/climbRate；coverage=sweep/nV+maxTransit（里程含各机转场）；rtl=最远机返场+下降；land=下降；start_formation=0.5min 就位估计。电量裕度 = 最低电量 − duration/endurance×100。输出一行摘要：`≈12.3 分钟｜8.4 km｜最低裕度 31%`，随计划摘要与候选卡片展示。

### WP2.4 拍卖法任务分配

**新文件**：`SwarmTaskAllocator.h/.cc`；集成 `SwarmMissionPlanner::planAndUploadCoverage` 第 5 参 `assignMode`（默认 sequential）

- Bertsekas auction：净价值 = −cost − price；bid = price + (best−second) + ε，ε=1/(n+1)
- **ε-最优界**：总成本 ≤ 最优 + nε（米级，Python 仿真 30 组随机对比全部满足）
- 反转场景（机在条带反序侧）：顺序分配 380 m → 拍卖 20 m，转场里程降低 95%
- 条带质心经 `latLonToLocalM` 投影后构造 cost 矩阵；分配结果置换 `bandOfVehicle` 映射，plannerFeedback 报告"总转场里程 X 米（顺序 Y 米，降低 Z%）"
- LLM 侧：`plan_coverage` schema 新增 `assign` 枚举（sequential/auction），系统提示规则 10 注明"用户要求最优分配/就近分配时用 auction"；未知值回退 sequential 并 warning

### WP2.5 模板库 9 套 + Schema v2

TaskTemplate 新增 `schemaVersion/tags/minFleet/requiredPayload`；`runTemplate` 执行前检查在线数 ≥ min_fleet（不足报错中止）+ 载荷提示；新增 `templateMeta()` 查询接口。

| # | 模板 | min_fleet | 要点 |

| 4 | 紧急降落 | 0 | 全停（P1 已有） |

### WP2.2 多候选方案

- 系统提示规则 8：用户要求"几个方案/候选/备选"或任务有多种明显不同实现时，调用 **propose_candidates**（第 17 工具，candidates 2~3 项：title/summary/pros/cons + actions 或 template_name+template_params 二选一）
- `_handleCandidates`：动作型走 parseAndValidate、模板型走 instantiate+parseStages，逐候选过约束校验+预演估算
- QML 候选对比卡片（青色边框）：标题/类型/⚠违例数/summary/优点(绿)/缺点(橙)/预演摘要(蓝)，"选择此方案"⇒ 正常确认管线，"全部放弃"丢弃

### WP2.3 计划可编辑

确认区勾选"编辑参数"后，每个动作展开参数文本框（初始值 `pendingPlanParamsJson[index]`，每动作一行 Compact JSON），点"更新"⇒ `updatePendingAction(index, paramsJson)` 合并参数（plan_coverage 的 lat/lon 自动转回 center 数组）⇒ 重新 parseAndValidate 生效，写审计 `plan_edited`。**务实裁剪**：未做 QGC Plan 视图深度互通，留后续阶段。

### WP2.6 性能埋点

`_sendRequest` 记录 `_requestStartMs` ⇒ `_handleResponse` 计算 `responseTimeSec`（Q_PROPERTY），面板配置区显示"上次响应 X.X s"，审计写 `dialog/llm_latency`。**务实裁剪**：未做 SSE 流式输出，留后续阶段。
