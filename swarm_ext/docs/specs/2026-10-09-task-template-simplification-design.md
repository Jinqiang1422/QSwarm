# 任务模板库精简（9 → 6 套）— 设计文档

> 日期：2026-10-09 · 定位：内置任务模板去重；不改模板引擎

## 1. 背景

AI 集群面板的任务模板库内置 9 套模板，其中两组实质重复：

| 类别 | 模板 | 实际差别 |
|---|---|---|
| 区域覆盖 | 区域搜索后返航 / 平行网格扫掠 / 扇形扫掠搜索 | 都是「起飞 → 在同一地图中心按 1 / 2 / 3 个角度条带覆盖 → 返航」；「扇形」并非分扇区，而是同一区域换三个角度扫 |
| 编队 | 编队巡航后返航 / 编队巡逻 / 会合集结 | 都是「起飞 → 开始编队 → 计时保持 → 停止编队返航」；会合集结 = 环形队形的编队巡航，编队巡逻 = 中途多换一次队形的两段巡航 |
| 其他 | 快速出动待命 / 全员返航降落 / 多机接力值守 | 各有用途，不重复 |

重复模板让操作员和大模型在相近的选项间犹豫，也增加了参数说明与评测维护成本。

## 2. 目标与非目标

**目标**：内置模板精简为 6 套、互不重复；已落盘的 3 套旧模板文件一次性退役；LLM 评测集同步到 v2。

**非目标**：不改模板引擎（不支持按参数决定阶段数）；不改保留的 6 套模板内容；不改历史文档中的模板描述。

## 3. 设计

### 3.1 模板集合

保留（内容不变）：区域搜索后返航、平行网格扫掠、编队巡航后返航、快速出动待命、全员返航降落、多机接力值守。

删除：扇形扫掠搜索、编队巡逻、会合集结。替代方式：

- 会合集结 → 「编队巡航后返航」，`formation = circle`、`spacing` = 集结半径、`cruise_seconds` = 保持时长
  （`spacing` 上限 100 米，原 `gather_radius` 上限 200 米）；
- 三角度扫掠、中途换队形 → 大模型自定义编排（`start_swarm_task`）或手工编写自定义模板（用户手册 15.6）。
  待确认任务的逐阶段编辑不能增删阶段，不能替代这两套模板。

代码：`SwarmTaskLibrary.cc` 删除三套的内置 JSON 常量、`_ensureDefaults` 落盘表与旧版摘要表中的条目、`_scan` 的内置名单
中的条目；`SwarmTaskLibrary.h` 头注释改为「内置模板 6 套」并列出名称。`swarm_ext/templates/`（`validate_assets.py`
要求与内置模板一致的副本）删除对应三个 JSON。

### 3.2 已落盘旧文件的一次性退役

内置模板首次启动落盘到 `AppDataLocation/SwarmTemplates`，之后按普通文件扫描；仅从代码删除时三个文件仍会出现在面板上。

- 模板目录新增版本标记文件 `.builtin-set-revision`（内容为整数）。
- 启动时（`_ensureDefaults` 之前）若标记不存在或小于 3：将 `扇形扫掠搜索.json`、`编队巡逻.json`、`会合集结.json`
  中存在者**一律**（不论是否被用户修改）改名为 `<原文件名>.retired.bak`；同名备份已存在时改为
  `<原文件名>.retired-<yyyyMMddHHmmss>.bak`。随后写入标记 `3`。
- 只在升级时执行一次：标记已为 3 时不再检查，因此用户之后自建的同名模板不会被退役。
- 每个退役文件记审计日志（`task_library / template_retired`，含文件名与备份名）；改名或写标记失败时经应用消息条
  提示并继续启动（失败时不写标记，下次启动重试）。
- 退役文件扩展名不是 `.json`，扫描时自然不再列出；内容完整保留，可手工改回恢复。

### 3.3 LLM 评测集 v2

`swarm_ext/tests/llm_eval/`：

- `generate_dataset.py` 默认输出改为 `dataset_v2.jsonl` 并生成之；`dataset_v1.jsonl` 与已有基线保持不变（基线仅对应 v1）。
- `run_eval.py` 默认数据集改为 v2；模拟上下文的 `templates` 名单改为 6 套。
- `swarm_ext/tests/validate_assets.py` 中「生成产物与入库数据集逐字节一致」的检查改为比对 `dataset_v2.jsonl`。
- 题目改写（以 v1 编号指代）：

| v1 题目 | v2 |
|---|---|
| E0171「会合集结模板，半径25米保持2分钟」 | 题面「按编队巡航模板做一次环形编队会合集结，半径25米保持2分钟」；期望 `run_task_template`「编队巡航后返航」`{formation: circle, spacing: 25, cruise_seconds: 120}` |
| E0172「会合集结模板，默认执行」 | 题面「按编队巡航模板做环形编队会合集结，默认参数」；期望同上，参数 `{formation: circle}` |
| E0168「编队巡逻模板，默认执行」 | 题面「编队巡航后返航模板，默认参数」；期望「编队巡航后返航」`{}` |
| E0162–E0164 扇形扫掠三题 | 题面去掉模板名、描述三角度依次扫掠（如「按0、60、120度三个角度对该区域依次扫掠搜索，完成后返航」）；归入 C_task；期望 `start_swarm_task` 5 阶段（起飞、三次扫掠、返航） |
| E0167「编队巡逻模板，楔形巡逻5分钟换纵队」 | 题面去掉模板名；归入 C_task；期望 `start_swarm_task` 6 阶段（起飞、楔形编队、巡逻 300 s、换纵队、巡逻、返航） |
| E0253、E0259 候选方案题；E0147 | 不改（只比工具名，或「编队巡逻」仅为自定义阶段名） |

  `start_swarm_task` 的评分规则不变（只比阶段数，不比 task_name）。README 写明 v2 相对 v1 的变化。
  D 类改写题保留「模板」字样：评测上下文只给模板名、不给参数说明，不点明模板时期望答案不唯一。

### 3.4 测试

- 枚举内置模板名称的测试（如 `SwarmRegressionTest::allTemplatesUseRuntimeContracts`）改为 6 套。
- 新增退役测试：
  1. 无标记、预置三个旧文件（其一内容已修改）→ 构建模板库后三者均为 `.retired.bak`、模板列表只含 6 套内置模板、标记为 3；
  2. 随后保存一个名为「会合集结」的用户模板并重建模板库 → 该模板仍存在；
  3. `.retired.bak` 已存在时退役为带时间戳的备份名。
- `validate_assets.py` 通过；生成脚本能产出 v2，`run_eval.py` 能加载 v2（不调用模型的自检路径，若无则只校验 JSONL 结构）。
- 完成标准按 AGENTS.md：容器内编译、`ctest -R "Swarm|Task"` 与完整 `-L "Unit|Integration" -LE "Flaky|Network"` 通过；
  clang-format、ruff（pre-commit 锁定版本）通过。

## 4. 风险

- 依赖已删模板名的外部脚本或用户习惯会失效：退役文件保留，可手工恢复为用户模板。
- 评测集 v2 与旧基线不可直接比较：README 注明，基线需在 v2 上重跑。
- `整体软件开发计划.md` 的 P2 退出标准写有「≥9 套模板可用」，精简后不再满足其字面要求；该计划属历史文档不改，
  是否调整指标口径由项目负责人决定。
