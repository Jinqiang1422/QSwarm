# 同步编队航段 — 设计文档

> 日期：2026-10-05 · 定位：行为改进（编队移动「长机先走、僚机后跟」，队形收敛不一致）
> 前置：`2026-09-30-formation-goto-fix-design.md`（随槽位平移 + 有界追赶、待 ACK 跳过、槽位自愈）

## 1. 背景与问题

编队运行中，操作员在地图上点击「飞往位置」或长机执行航线时，总是长机先走、僚机再各自跟上，
队形散乱、到位时间不一。根因在控制结构本身：

- **P1 僚机只能追长机**：长机收到一条 `DO_REPOSITION` 即按巡航速度飞向目标；僚机以 1 Hz 收到
  「长机**当前**位置 + 槽位偏移」，且每条都按「到点即停」执行。长机先动，僚机后动。
  9/30 SITL 实测：途中僚机拖后约一个间距（误差 15–19 m），长机到达后约 7 s 才收敛。
- **P2 队形随长机瞬时航向甩动**：槽位按长机航向计算。PX4 收到 goto 先把机头转向目标，
  整个队形绕长机旋转，僚机在起步阶段画大弧线。
- **P3 追赶慢且各自为政**：追赶限速 2 m/s，各僚机独立追各自槽位，距离远的到得晚；
  启动/变队形时同样如此，收敛时间参差。
- **P4 起始间距死锁**（9/30 遗留）：SITL 1、2 号机出生点相距约 2.5 m，低于最小间距 3 m，
  逐点间距检查使 2 号机长期不受令。

航线场景（长机执行 AUTO 任务、僚机跟随）与单点 goto 同属上述结构，问题相同。

## 2. 目标与非目标

**目标**

- 编队移动时全队（含长机）同时起步、同时到达，途中保持队形，队形朝向随航向「边飞边转」。
- 编队启动、切换队形/间距时，全队同步收敛到槽位。
- 编队可按长机已上传的航线逐点飞行，每个航点全队对齐后再飞下一段（操作员 2026-10-05 确认
  接受航点处减速对齐）。
- 任何时刻任意两机间距不低于约束下限；本就过近的机对不允许在途中更近。

**非目标**

- 过航点不减速的连续编队飞行（需 OFFBOARD 高频设定点，本次不做）。
- ArduPilot 速度同步：基类退化为不带速度的 goto，可飞但不同步。
- AI 指令（LLM 工具）触发编队航线：以后可在动作表加 `formation_route`。
- 停止编队时主动让各机悬停：保持现有「停止不改飞行模式」语义。
- 不改 `maxGoToLocationDistance`、不改引导动作抽屉交互。

## 3. 设计

### 3.1 组件划分

| 单元 | 职责 | 依赖 |
|---|---|---|
| `FormationLegPlanner`（新，纯函数） | 由各成员当前位置、槽位几何、目标参考点、朝向、编队速度生成**航段计划**：每机起终点、速度、统一时长；含槽位分配、成对间距闭式校验、自动拆段、区域检查 | `QGeoCoordinate` |
| `FormationLegTracker`（新，纯状态机） | 输入航段计划与每拍实测位置，输出需重发指令的成员及新速度、完成/超时/中止判定 | 航段计划 |
| `FormationController`（改） | 新增两阶段：`StationKeeping`（现有 1 Hz 长机-僚机保持）与 `Transit`（执行航段队列）。航段期间暂停保持逻辑；负责租约检查、待 ACK 跳过、指令下发、ACK 结果监听 | 上两者 + `Vehicle` |
| `FirmwarePlugin`（新增虚函数） | `guidedModeGotoLocationAtSpeed(vehicle, coord, groundSpeed)`：PX4 覆写为 param1 带地速的 `DO_REPOSITION`；基类退化为 `guidedModeGotoLocationAndAltitude` | — |
| `SwarmManager`（改） | 地图 goto 改走编队航段；新增 `startFormationRoute()`；区域约束回调与间距检查拆分 | — |
| `SwarmControlPanel.qml`（改） | 编队区新增「编队按航线飞」按钮与确认框，状态文本显示航段进度 | — |
| `SwarmAcceptanceServer`（改） | `status` 增加航段阶段/序号/每机进度；新增 `formation_route` 命令 | — |

goto 与航线航段中长机也由编队控制器下发指令，因此**长机也须持有自动控制租约**，否则拒绝发起航段
（启动/变队形的原地航段不指挥长机，见 3.2 第 8 条）。
不在航段中时保持逻辑不变：长机被其他方式驱动（原生任务、手动）时僚机仍按现有方式跟随。

### 3.2 航段规划（`FormationLegPlanner`）

计算在以长机当前位置为原点的局部东-北-天坐标系中进行。

1. **终点朝向 H**：goto 取长机当前位置 → 点击点的方位角；航线第 k 段取上一航点（第一段用
   长机当前位置）→ 本航点的方位角；水平位移小于编队间距时保持当前朝向（不为小位移转队形）；
   原地航段（启动/变队形）取当前编队朝向（启动时即长机航向；之后为上一航段结束时的朝向）。
2. **终点槽位**：长机位于参考点；僚机槽位沿用 `_formationOffset` 几何，按 H 旋转；
   高度 = 参考高度 + 分层（goto 参考高度取长机当前高度，航线取航点 AMSL 高度）。
3. **槽位分配**：长机不参与；僚机以匈牙利算法求「起点→终点距离平方和最小」的分配（CAPT 思路，
   同步直线轨迹下天然避免交叉）。当前分配代价与最优相差 < 5% 时保持当前分配，避免为微小收益互换。
   多段航段（拆段、航线）共用同一分配。
4. **速度同步**：每机水平航程 d_i，统一时长 T = max(d_i)/V，每机速度 v_i = d_i/T。
   编队速度 V 默认 5 m/s，且不超过各机 `maximumHorizontalSpeedMultirotorMetersSecond` 最小值的 80%，
   为共识调速留余量。垂直方向不同步，交由 PX4 升降速率。
5. **成对间距闭式校验（含长机）**：同步直线运动下两机相对位置 r(s) = r₀ + s·Δ（s∈[0,1]），
   最小值在 s* = clamp(−r₀·Δ/|Δ|², 0, 1) 处精确取得。判据：
   令 m = min(|r(0)|, |r(1)|)，要求 `min_s |r(s)| ≥ required`：m ≥ D_min + 1 m 时 required = D_min + 1 m；
   D_min ≤ m < D_min + 1 m 时 required = D_min（起止已在跟踪余量之内，可接近到硬下限但不得低于它）；
   m < D_min 时 required = m（本就低于下限的机对不允许更近）。终点间距须 ≥ D_min；两条路径都静止的机对跳过。
   D_min 为约束配置 `minSeparationM`（默认 3 m），1 m 为跟踪余量。（2026-10-08 SITL 发现原判据
   `min(D_min + 1 m, |r(0)|, |r(1)|)` 对出生队列中 3.1 m 的机对过严——分层时上下换位使间距降到 3.0 m 即被拒——故按上式放宽。）刚体平移时相对位置不变；
   转过 θ 时途中间距最多缩至 cos(θ/2) 倍，故只有大转角可能不通过。
   不参与本次移动但已离地的编队成员（失效保护中、刚起飞、租约过期、尚无槽位等）作为静止障碍物一并参与校验。
6. **自动拆段与分层兜底**：不通过时把参考位置、高度、朝向在起止间均分为 k = 2、3、4 小段
   （每段转角 θ/k），逐段校验；小段之间全队对齐。均分只能化解大转角；若僚机须横穿长机所在位置
   （例如 SITL 出生队列中长机在一端、僚机全在同侧），改用**垂直分层**三段：各机先只做垂直移动，
   升到互不相同的高度层（长机留在原高度，僚机按当前高度由低到高逐层升高——保持抬升阶段的上下次序，层距 = D_min + 1 m）；
   再在各自高度层内水平移到终点正上方；最后垂直回到槽位高度。三段同样逐段校验。
   尝试顺序：当前分配（代价接近最优时）不分层 → 最优分配不分层 → 最优分配 + 分层。
   全部不通过：goto/航线拒绝执行并报告机对与最小间距；启动/变队形退回现有逐机追赶（不劣于现状）。
7. **区域检查**：每条路径用现有 `SwarmConstraintChecker::segmentAllowed` 做线段级电子围栏检查
   （含跨越禁飞多边形边界），并检查终点高度：不低于该机 Home − 0.5 m、不高于 Home + 最大高度
   （Home 未知则拒绝）。检查返回具体原因（约束配置无效 / Home 未知 / 低于 Home / 超出高度上限 /
   越出电子围栏），拒绝时报告「N 号机航段被拒绝：原因」。每次规划只取一次约束配置快照（最小间距与
   路径检查同源）。复用约束配置，但从现有「目标点 vs 他机当前位置」的回调中拆出独立的路径检查；
   航段内间距由第 5 步负责。
   `StationKeeping` 仍使用现有的组合检查（区域 + 对他机当前位置的间距），行为不变。
8. **原地航段不指挥长机**：启动/变队形的航段只下发给僚机，长机保持其当前行为（可能正由原生任务或
   手动驱动）。若长机水平速度 > 1 m/s，原地航段的终点会随长机漂移，此时不发起同步航段，直接用现有
   逐机追赶。

### 3.3 执行与共识调速（`FormationLegTracker` + `Transit` 阶段）

- **起步**：同一拍向全体成员下发 `DO_REPOSITION(终点, v_i)`；param4（航向）传 NaN——PX4 v1.15
  把 param4 当弧度直接使用，与 MAVLink 规范的「度」不一致，故不传，由 PX4 默认机头对准各自终点，
  平行飞行时朝向自然一致。某机上一条指令待 ACK 时下一拍补发，晚起步由共识调速追平。
- **每拍（1 Hz）共识调速**：
  - 进度 s_i = 实测位置在「起点→终点」上的投影比例，clamp 到 [0,1]；航程 < 0.5 m 的机不参与统计。
  - 共识进度 s̄ = 参与成员均值；掉队量 e_i = (s̄ − s_i)·d_i（米，正值为落后）。
  - 新速度 v_i' = clamp(v_i + 0.5·e_i, 0.5·v_i, 0.9·最大水平速度)。
  - 仅当与上次下发相差 ≥ 0.3 m/s 且无待 ACK 指令时重发（同一终点，PX4 从当前速度平滑重规划）。
  - 某机卡住时他机降至 0.5·v_i 等待：「保持队形优先于准时」。偏离同步理想位置超过 5 m（间距判据只为 1 m 跟踪
    误差留了余量）即终止航段，交回保持阶段（逐拍间距检查）；超时（2T + 20 s）作最终兜底。
- **完成**：全员距终点水平、垂直均 ≤ 1.0 m 判本段完成；航线进入下一段，全部完成后回到
  `StationKeeping`，槽位沿用规划分配。保持阶段槽位方向仍取长机航向——长机到达时航向 ≈ H，
  不会再甩动。
- **超时**：本段耗时 > 2T + 20 s 时提示「航段超时：N 号机未到位」，终止航线，回到保持阶段。
- **中断与异常**：

  | 事件 | 处理 |
  |---|---|
  | 运行中再次 goto | 放弃当前航段/航线，从各机当前位置重新规划 |
  | 停止编队 | 清空航段，不追加指令；各机继续飞向当前航段终点（已通过间距校验，最远可达一个航段长度）。提示操作员「如需原地悬停请用『暂停』」；AI 工具描述同步更正 |
  | 成员被切换出引导模式（操作员单机降落/返航、任务开始航线、手动模式等） | 该机确认进入引导模式（PX4 为 Hold）之后若模式改变，僚机移出**当前航段**，长机终止航段。否则 1 Hz 调速重发的 DO_REPOSITION（带 CHANGE_MODE）会覆盖操作员的指令。局限：①航段结束后保持阶段仍会再次指挥该僚机（与 9/30 一致，要彻底离队须由任务/操作员撤出编队）；②PX4 上单机「暂停」「改高度」本身就是保持 Hold 的 DO_REPOSITION，不触发模式变化，航段中仍会被下一次调速覆盖——航段中要原地停下请用集群面板的「暂停」或先停止编队；③模式变化有约 1 s 心跳滞后 |
  | 僚机离队（上锁、租约失效、返航/降落等恢复动作） | 移出航段，其余继续——剩余机对已两两校验 |
  | 长机离队 | 终止航线，走现有长机交接 |
  | 某机 ACK 非 ACCEPTED | 立即终止航段，提示「N 号机拒绝航段指令」，回到保持 |
  | 长机无自动控制租约 | 拒绝发起航段并说明原因 |
  | 成员处于失效保护（HEARTBEAT system_status ≥ MAV_STATE_CRITICAL） | 不再向它下发任何指令：僚机视同离队，长机则终止航段并阻塞编队。PX4 把每条带 CHANGE_MODE 的 DO_REPOSITION 当作一次模式切换，在失效保护的悬停延迟窗口（COM_FAIL_ACT_T）内收到会取消返航/降落；保持阶段同样适用。残余窗口：PX4 以 1 Hz 发心跳，失效保护开始后约 1 s（加链路时延）内地面站尚不可见，此间保持阶段的指令仍可能落入延迟窗口；该窗口早于本功能存在（保持阶段一直每拍重发），本设计只缩小、未消除。后续可在保持阶段加重发死区（目标不变时不重发） |

- **可观测性**：审计 `formation / leg_planned`（时长、速度、分配）、`leg_started`、
  `leg_completed`（实际耗时、最大掉队距离）、`leg_aborted`（原因）、`route_started` /
  `route_completed` / `route_aborted`。状态文本如「编队航段 2/3：同步飞行中，预计 30 s」。

### 3.4 入口

**地图「飞往位置」**（`SwarmManager::gotoLocation`）：编队运行中对**编队正在引导的成员**（长机，或
已离地、有租约、未处于失效保护的僚机）goto，均改为编队整体航段，长机终点为点击点、高度保持长机当前
高度（与原生 goto 一致）；审计 `formation / operator_goto_formation_leg`，反馈「编队整体飞往目标点：
N 架同步，预计 X s」（N 为实际受令架数）。规划失败时拒绝并给出原因，**不**退回「仅长机飞往」；
因长机级原因（长机离队、失效保护、无租约）拒绝时提示「如需单机飞往请先停止编队」。单个僚机的保持
目标无效不阻止 goto（新航段由规划器重新校验）。编队未运行、目标机不在编队内或编队未在引导它
（如失效保护返航中的僚机、未离地的成员）时行为同原生 QGC。9/30 的 `operator_goto_via_leader`
由此取代，相关测试按新行为更新。

**反馈**：航段结束经 `transitFinished(success, reason, kind)` 以队列连接转为操作员反馈；自动的原地
变队形（kind = reshape）与「被新航段替换」不弹反馈（状态文本可见），程序关闭后不再反馈。

**「编队按航线飞」按钮**：编队运行时可用（不因单个僚机的保持目标无效而禁用；是否可执行由确认摘要判定，不可执行时确认框只提供「确定」）；点击后弹确认框（如「长机 1 的航线：5 个航点，
总长 820 m，预计 3 分 10 秒」），与面板其他确认一致。确认框生成时记下长机编号与航线指纹
（`SwarmMissionSnapshot::fingerprint()`），执行前核对；长机交接或航线被重传则拒绝并提示「长机或航线
已变化，请重新确认」，不执行未经确认的航线。读取长机 `missionManager()` 已上传航线，
复用 `SwarmMissionSnapshot` 处理坐标系、Home 占位与相对高度换算：

| 航线项 | 处理 |
|---|---|
| 首项 `NAV_TAKEOFF` | 跳过（编队已在空中） |
| `NAV_WAYPOINT` | 每个航点生成一个编队航段；带悬停时间（param1 ≠ 0）、非自动继续（autoContinue = 0）或高度低于 Home 0.5 m 以上的航点整条拒绝（编队逐点对齐不实现悬停，静默忽略会让预计时长与实际不符） |
| 末项 `NAV_LAND` / `NAV_RETURN_TO_LAUNCH` | 不由编队执行；航线止于最后一个航点，确认框注明「末尾降落/返航需另行操作」 |
| 其他任何指令（DO_ 类、盘旋、相对地形高度等） | 整条拒绝，列出不支持项 |

航线执行中再 goto 或停止编队即中止航线。面板「开始任务」（原生 AUTO）语义不变。

**验收接口**：新增 `formation_route` 命令，与按钮同一入口；新增 `upload_route` 命令（给指定机写入
航点航线，供 SITL 脚本准备 S3 场景）。`status.formation` 增加 `heading_deg`（编队朝向）、`slots`
（僚机 id → 槽位编号）与 `transit`（阶段、航段序号、每机起终点/速度/进度、上次航段结果）。

### 3.5 已知限制（2026-10-07 整体审查后）

- 停止编队不让飞机悬停：各机飞完当前航段（最远一个航段长度）；原地停下用「暂停」。
- 间距保证以「同步直线执行、跟踪误差 ≤ 1 m」为前提：垂直运动不同步；飞行中再次 goto 不考虑当前速度；
  静止障碍物（不参与本次移动的已离地成员）取规划时刻的快照，失效保护返航中的成员仍在移动。
  偏离同步位置超过 5 m 即终止航段（实飞中刹车过冲可能触发，见 SITL 记录）。
- 失效保护对保持阶段仍有约 1 s 残余窗口（心跳 1 Hz）。
- 编队朝向在长机悬停或慢于 1 m/s 时冻结：偏航长机不会旋转队形，只有至少一个间距的 goto 或航线航段会。
- 航线：仅普通航点，逐点对齐，无电量/续航检查，不受 maxGoToLocationDistance 限制，末尾降落/返航需另行操作。
- ArduPilot 不做速度同步；AI 不能发起编队航线。
- 同步原地变队形只在启动或改队形时已离地的僚机上发生；之后才起飞的僚机走逐机追赶。
- 到达判据为水平、垂直均 ≤ 1 m，真机 GPS 噪声可能导致航段超时。
