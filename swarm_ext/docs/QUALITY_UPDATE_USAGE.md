# 软件质量改进使用说明

本说明补充《用户使用手册》，描述 2026-09-08 质量审查后的行为变化。

## 局部退出与整体中止

在多阶段任务执行中，选中部分成员后点击暂停、返航或降落，这些成员退出当前
自动任务与编队。它们不会被后续阶段的目标选择重新加入；其他成员继续原任务。
没有选择成员时，批量按钮仍作用于全部在线成员。

长机退出时，在剩余成员中选择已解锁、已升空、定位有效且仍持有自动控制权的继任者。
交接按当前相对位置建立偏移，避免直接重新分配所有编队位置。缺少合格继任者时
编队引导显示阻塞；仅剩一名成员时停止编队引导。

“中止任务”撤销该任务成员尚未执行的动作、停止其编队引导并发送暂停。
已发送的机载任务和飞控命令无法从传输链路撤回，应查看逐机状态和遥测确认响应。
要让退出成员重新参加，须明确启动新的操作员指令或新的任务。

## 动作执行与任务状态

集群面板分别显示逐机动作状态和航线上传状态。“等待下发”“等待响应”表示动作尚未完成；
动作确认表示已获得对应命令响应或目标遥测，不表示整个飞行任务完成。
部分成员失败时，尚未下发的后续动作会被取消，已执行成员保留当前机载行为。

覆盖规划会经历上传、飞控确认、回读核验三个环节，只有核验成功才允许同一自动流程
继续启动航线。PX4 与 ArduPilot 使用各自的 Home 处理策略。上传忙碌、失败、回读不一致，
或者后续阶段启动前航线版本变化，均会阻止自动启动。

动作全部完成后才开始计算阶段持续时间。尚未派发动作的阻塞阶段可以修正后重试；
已经部分派发的失败阶段需要中止并重新启动，避免重复飞行动作。

## 航线完成确认

自动完成要求当前执行已启动、观察到任务活动状态，并收到同一任务版本的明确完成状态。
上锁、退出 Mission 模式或仅收到一条“完成”消息都不能单独证明任务完成。

固件没有提供可靠完成状态时，界面显示“确认机载任务已完成”。操作员核对涉及成员后，
通过确认对话框继续。确认绑定当前任务、阶段和执行编号；过期确认不会推进新的阶段。
飞控报告任务暂停、任务不存在，或机载任务版本已变化时，确认会被拒绝。

## 模板参数

六套内置模板统一使用运行时解析器验证。输入必须是完整有限数值，非法文本和越界值
直接报错。接力模板默认按实际目标集合分组，分组不得重叠、遗漏目标或包含未选中成员。
未手动填写升空判定高度时，系统会根据起飞高度推导；显式填写时不得高于起飞高度。
长时间持续阶段自动获得足够的超时时间。

未修改过的旧内置模板通过内容摘要识别，升级前创建 `.pre-revision-2.bak` 备份，
然后原子写入新模板。自定义或修改过的模板保留原内容，执行时仍须通过新的参数校验。
模板或任务状态保存失败会显示错误。

## 感知服务升级

QGC 和 Python 感知服务须同时升级到 v2，旧发送端不会自动兼容。
默认只接收本机感知流；远程接入需要显式设置监听地址和来源白名单。
心跳到期会更新离线状态，重新连接不会沿用上次监听的分片与统计。
详细部署和字节格式见 [感知协议 v2](PERCEPTION_PROTOCOL_V2.md)。

## RC 参数映射

RC 参数映射对话框绑定打开时的车辆及真实参数 Fact。活动车辆切换、车辆断开、
参数对象销毁或尚未完成参数更新时，提交不可用。提交时重新检查数值范围，且要求
最小值 ≤ 中心值 ≤ 最大值。车辆切换后应关闭对话框并为目标车辆重新打开。
