## 1. 软件定位与核心原则

本软件在开源 **QGroundControl**(master / v5.x)之上二次开发,面向**多无人机集群**的指挥控制,提供三大能力域:

- **域① 大模型集群指挥** — 用自然语言下达集群任务,大模型解析为动作序列,经三道安全闸门校验后下发。
- **域② 多机感知态势汇聚** — 汇聚各机视频/航迹,融合为共同作战态势图(COP),叠加在飞行地图上。
- **域③ 人机协同任务规划** — 区域覆盖、编队、多阶段任务、协同战术(搜索/巡逻/跟踪/围捕/拦截)的规划与执行。

### 三条不可动摇的设计原则

1. **大模型不直接控飞机** — 大模型只产出「工具调用」,统一交回校验层→安全闸门→下发。校验代码路径与大模型进程严格分离。
2. **人在回路** — 含危险动作的计划默认挂起,必须操作员确认后才执行(可按自主等级放宽)。
3. **操作员优先** — 操作员随时可在 QGC 手动接管任一无人机,集群会立即对该机让出控制。

## 2. 运行环境与启动

- **平台**:桌面 QGroundControl(Linux / Windows / macOS)。集群与大模型模块为内嵌 C++,随主程序一同启动,无需单独进程。
- **网络**:使用云端大模型时需能访问对应 API 端点;使用本地 Ollama 时可离线。
- **无人机接入**:与标准 QGC 相同(串口 / UDP / TCP 链路)。多机场景下每架机用不同 MAVLink 系统号(sysid)接入。

启动后进入**飞行界面(FlyView)**。**只要接入至少 1 架无人机**,集群面板便自动出现在界面左上区域;未接入无人机时面板隐藏。

## 3. 界面总览

集群扩展在飞行界面提供 **2 个常驻面板 + 1 个地图图层**,数据统一来自单例 `swarmManager`:

| 组件 | 位置 | 作用 |
|---|---|---|
| **集群指挥控制面板** `SwarmControlPanel` | 左上,工具条下方常驻 | 多机监控、一键指令、编队、区域覆盖任务 |
| **AI 集群指挥面板** `SwarmAIPanel` | 集群面板正下方常驻 | 大模型配置、自然语言指挥、计划确认、任务状态机、模板库、感知/态势 |
| **集群态势叠加层** `SwarmSituationLayer` | 叠加在飞行地图上 | 只读观察:目标航迹、威胁/禁飞区、搜索覆盖热力 |

> 两个面板均由「是否有无人机接入」自动显隐,**没有总开关按钮**;每个面板标题栏右侧有**「展开/收起」**按钮可折叠。态势图层默认全开、无独立开关。

## 4. 大模型接口配置

在 **AI 集群指挥面板** 标题栏点击 **「配置」**,展开接口配置区:

| 输入项 | 说明 | 默认 / 示例 |
|---|---|---|
| **接口地址** | OpenAI 兼容端点 base URL | `https://api.deepseek.com/v1` |
| **API Key** | 密钥(密码框,不回显) | 空,需自行填写 |
| **模型** | 模型名 | `deepseek-chat` |

- 填好后点 **「测试连接」** 验证(会请求 `{接口地址}/models`)。
- **危险动作需人工确认**(复选框):建议保持勾选。
- **工具调用(Function Calling)**(复选框):默认开启;若所用端点/小模型不支持工具调用,取消勾选走 JSON 回退模式。

### 支持的提供商

任何 **OpenAI 兼容**端点均可,已验证/适配:**DeepSeek / Kimi(月之暗面)/ 通义千问 / OpenAI / Ollama 本地**。

**云端 ↔ 离线切换**:无专门开关,直接改「接口地址 + 模型」即可——填本地 Ollama 的 OpenAI 兼容地址与本地模型名即离线运行。

> 配置通过系统设置(QSettings)持久化,下次启动自动读取,也可随时在面板改写。请求参数固定 `temperature=0.2`。

## 5. 自主等级 L1 / L2 / L3

在 AI 面板配置区的 **「◆ 自主等级」** 下拉切换,右侧实时显示等级说明。默认 **L2**。

| 等级 | 名称 | 行为 |
|---|---|---|
| **L1** | 仅建议 | AI 只生成并展示计划,**一律不下发**;操作员手动直控不受限 |
| **L2** | 监督执行(默认) | AI 计划经**人工确认**后下发;含危险动作的计划**强制挂起确认** |
| **L3** | 限定域自主 | **白名单**任务域内动作自动执行(仍过校验闸门 + 全程审计);域外危险动作仍需确认;**紧急类动作永不自动** |

### L3 白名单

选择 L3 后出现白名单勾选区,可勾选免确认自动执行的危险动作:
`arm(解锁) / takeoff(起飞) / land(降落) / rtl(返航) / start_mission(开始任务) / disarm(上锁) / start_formation(开始编队)`。

> **紧急上锁(emergency_disarm)在任何等级都不会自动执行**,必须人工确认。

## 6. 集群指挥控制面板操作

面板标题显示 `集群指挥控制 (N 架)`。分四个区块。

### 6.1 多机实时监控(点击行选中/取消)

- 每架无人机一行,显示:**ID、解锁/上锁状态、飞行模式、相对高度、地速、首块电池电量%**。
- **点击整行**切换选中/取消;选中行高亮,绿框表示当前活动机。
- 底部:**「全选」**、**「全不选」**,右侧显示 `已选 N 架`。
- 后续一键指令**有选中则只作用于选中机,无选中则作用于全部在线机**。

### 6.2 集群一键指令

先在 **「起飞高度(米)」** 填目标高度(默认 10,范围 2–120),再点按钮:

| 按钮 | 作用 | 二次确认 |
|---|---|---|
| **解锁** | 批量解锁 | 否 |
| **上锁** | 批量上锁 | 否 |
| **起飞** | 批量起飞到设定高度(未解锁机自动先解锁;机间错开约 2.5 秒) | 是 |
| **降落** | 批量原地降落 | 是 |
| **返航** | 批量返航(RTL) | 是 |
| **暂停** | 批量暂停/悬停 | 否 |
| **开始任务** | 批量开始已上传航线 | 否 |
| **紧急上锁** | 强制上锁(含空中) | 是（红色警告） |

> ⚠️ **紧急上锁警告**(原文):「飞行中强制上锁将导致坠机！仅在地面紧急情况下使用。」

批量指令默认机间错开约 **300 毫秒**下发,避免链路瞬时拥塞。**已被操作员手动接管的机会被自动跳过**(见 §11.3)。

### 6.3 编队飞行

| 控件 | 选项 / 默认 |
|---|---|
| **队形** | 楔形 / 纵队 / 横队 / 环形 |
| **长机** | 从在线机中选一架为长机 |
| **间距(米)** | 默认 10,范围 2–500 |
| **高度分层(米)** | 默认 3,范围 0–50 |

操作:设好参数 → **「开始编队」**(需在线机 > 1 架且当前无编队)→ 结束点 **「停止编队」**(僚机悬停)。右侧显示编队状态文案。

### 6.4 区域覆盖任务(中心取当前地图中心)

先把地图中心移到目标区域,填入:

| 参数 | 默认 |
|---|---|
| 长(米) | 200 |
| 宽(米) | 120 |
| 角度(度) | 0（0–359) |
| 行距(米) | 20（2–1000) |

- **「生成并上传」**:按机数划分条带、生成割草机航线并上传到各机。
- **「清空任务」**:清空各机航线。
- **「开始任务」**:各机开始执行航线。

## 7. AI 自然语言指挥

在 AI 面板底部输入框直接下达任务(例:`全体起飞到30米后楔形编队`),点 **「发送」**(回车等效)。**「新会话」** 清空对话历史。

### 交互流程

```
输入文本 →（防注入过滤）→ 大模型解析为动作序列 →（安全闸门校验）→
   ├─ 计划确认区:逐条审查 → 「确认执行」/「放弃」
   ├─ 候选方案对比:多方案择一 → 「选择此方案」
   └─ 文字追问:意图不清时 AI 反问补参数
```

### 7.1 计划确认区(人在回路)

当 AI 产出待确认计划时出现:
- 含危险动作时**红框 + ⚠ 标题**,逐条列出动作。
- 勾选 **「编辑参数」** 后每条动作出现 JSON 输入框(例 `{"altitude": 40}`),改完点 **「更新」**。
- 底部 **「确认执行」** 下发 / **「放弃」** 取消。

### 7.2 候选方案对比

当 AI 给出 2~3 个候选方案时出现,每张卡片显示:标题、违例数标记(如 `⚠2项违例`)、摘要、**优/劣/预演**信息。点 **「选择此方案」** 执行,或 **「全部放弃」**。

### 7.3 AI 能调用的工具(18 个)

大模型仅能通过以下受控工具间接操作(均经校验闸门):

- **集群指令**:`set_selection`(选机)、`arm`、`takeoff`、`land`、`rtl`、`pause`、`start_mission`、`disarm`、`emergency_disarm`、`clear_missions`
- **编队**:`start_formation`、`stop_formation`
- **区域规划**:`plan_coverage`(分配策略 sequential / auction / cbba)
- **协同战术**:`plan_tactic`(track / encircle / intercept / patrol,**仅出方案不下发**)
- **任务编排**:`start_swarm_task`、`abort_swarm_task`、`run_task_template`
- **多候选**:`propose_candidates`

### 7.4 大模型行为约束(内置)

- 只能使用态势中**真实存在**的无人机 ID,不得编造。
- 参数自动限幅:高度 2–120 米、间距 2–500 米、区域边长 10–100000 米、角度 0–360 度,超限取边界值。
- 态势问答须标注来源角标 `[遥测] / [感知] / [推测]`,态势中没有的数字不编造。
- 意图不清或缺关键参数时**不调用工具**,改用文字追问。

## 8. 多阶段任务与模板库

### 8.1 任务状态机

启动多阶段任务(经 AI `start_swarm_task` 或模板库)后,AI 面板出现 **「◆ 任务状态机」**:
- 显示任务名与当前状态文案,逐阶段用 `✓ 已完成 / ▶ 进行中 / ○ 未开始` 标记。
- 状态机监控航线进度**自动推进**;需人工确认的阶段出现 **「继续（人工确认）」** 按钮。
- **「中止任务」** 随时可终止(全体暂停)。

### 8.2 任务模板库

**「◆ 任务模板库」** 区:
- **「刷新」** 重新加载模板;**「打开目录」** 打开模板文件夹。
- 每个模板卡片显示名称、阶段数、描述,按模板参数动态生成输入表单。
- **「执行」** 按填入参数启动;非内置模板可 **「删除」**。

内置 **9 套模板**:区域搜索 / 编队巡逻 / 扇形扫掠 / 平行网格 / 接力值守 / 会合集结 / 快速出动 / 编队巡航 / 全员返航。

## 9. 协同战术规划

通过 AI 工具 `plan_tactic` 触发(自然语言,如「对目标 X 做环形跟踪，半径 150 米」),提供五类典型场景的教科书级基线算法,**均为规划建议级(L1),仅出方案供操作员确认,不直接下发**:

| 场景 | 说明 |
|---|---|
| **协同搜索** | 矩形区域按机数切无缝条带 + 就近分配(亦可用 §6.4 区域覆盖) |
| **协同巡逻** `patrol` | 多边形周界按弧长均分 + 相位错开 |
| **协同跟踪** `track` | 目标周围定半径观测环、相位均分 |
| **协同围捕** `encircle` | 环形包围点 + 就近分配,半径可收缩 |
| **协同拦截** `intercept` | 碰撞三角解算最早拦截点/航向/时间/可行性 |

## 10. 感知态势与态势图层

### 10.1 感知链路

在 AI 面板感知区:
- 状态行显示 `● 感知链路在线｜心跳 XHz｜目标 N 个｜线路时延 Xms` 或 `○ 感知链路待机（端口 X）`。
- **「启动 / 停止」** 按钮启停感知接收(默认 UDP 端口 **15600**)。
- **「周期态势摘要」**(复选框)+ **「间隔(s)」**:定期把态势摘要送给大模型,用于态势问答。

感知数据来自独立的 Python 感知服务(YOLO 类检测 + 多目标跟踪 + 像素↔地理坐标转换),经 UDP/TUNNEL 回传结构化航迹。

### 10.2 态势叠加层(只读观察)

叠加在飞行地图上,无需操作:
- **威胁区/禁飞区**:红色半透明多边形。
- **搜索覆盖热力**:琥珀色格网,越搜过越淡——回答「哪片还没搜」。
- **目标航迹**:每个目标一个图标 = 置信度环 + 类别色点(1 人员紫 / 2 车辆红 / 3 船只蓝 / 4 动物绿 / 5 火点橙 / 6 烟雾灰)+ 底部 `#编号 速度m/s`。

## 11. 安全机制

四道相互独立的安全防护,对大模型与人工指令一视同仁。

### 11.1 防注入过滤(第一道)

所有输入文本先过防注入过滤器,按累计权重三级判定:

| 级别 | 阈值 | 行为 |
|---|---|---|
| **blocked 拦截** | 分值 ≥ 5 | **不发送给大模型**,提示「输入被安全过滤拦截」 |
| **suspicious 可疑** | 分值 ≥ 2 | 放行但提示「包含可疑模式，已记录审计并继续」 |
| **clean 放行** | 其余 | 正常处理 |

覆盖中英文注入模式(忽略先前指令、绕过安全、套取系统提示、越狱/开发者模式/角色劫持等)。无论哪级都写审计。

### 11.2 约束校验闸门(10 条规则)

计划下发前 / 多阶段任务每阶段推进前自动校验。**error 级阻断下发,warning 级仅提示**:

| 规则 | 触发 | 级别 |
|---|---|---|
| 空域围栏 | 作业区在允许空域外 / 落入禁飞区 | error |
| 起飞高度 | 超过围栏高度上限 | error |
| 航程电量 | 估算耗电 > 可用电量 | error |
| 电量裕度 | 裕度不足 15% / 机队电量未知 | warning |
| 链路覆盖 | 最远作业点超链路半径 ×1.5 / ×1.0 | error / warning |
| 编队间距 | < 3 米 / < 6 米 | error / warning |
| 多区去冲突 | 两作业区距离过近可能重叠 | warning |
| 机队规模 | 在线机数 < 模板要求 | error |
| 载荷匹配 | 模板要求载荷但机队能力未知 | warning |

围栏/空域配置见 `SwarmConfig/fences.json`(§12)。

### 11.3 控制租约(操作员优先)

每架机监听飞行模式变化:
- **让出控制**:自动化持有租约期间,操作员把某机切到**自主模式集合之外**(手动直控如 Position/Manual、Offboard 外部控制、或未知模式)→ 集群立即对**该机**标记「人工接管」;排队指令在真正触发时会复检,持续编队与任务上传也会跳过该机,**其余机不受影响**。初始以手动模式接入不会被误判为“正在接管”。
- **恢复**:操作员把该机切回自主模式(任务 Mission / 悬停 Hold / 返航 RTL / 智能返航 / 降落 Land / 跟随 Follow / Goto / Takeoff)→ 解除接管;此后不会补发旧的排队指令,持续编队或下一轮自动化流程会重新申请控制。
- 判定基于固件规范的飞行模式(与界面显示同源,**多语言环境安全**);控制租约不持久化,重启回到观察态。

> **自主模式集合**:任务 / 悬停 / 返航 / 智能返航 / 降落 / 跟随 / Goto / Takeoff。模式名来自 Vehicle/FirmwarePlugin 规范访问器,不硬编码翻译文本。

### 11.4 全程审计

每次会话生成一个 JSONL 审计文件,逐行记录:用户输入及过滤判定、大模型请求与输出、校验结果、计划挂起/确认/拒绝、动作下发、人工指令、任务事件、模板运行、自主等级变更、安全闸门拦截、大模型时延等。
- AI 面板 **「导出当前会话」** 可导出审计到 `SwarmAudit/exports/`。
- 面板显示 `会话 / 已记录 N 条 / 审计目录` 与上次响应时延。

## 12. 配置文件与数据目录

均位于系统应用数据目录(`AppDataLocation`,随操作系统而定):

| 路径 | 内容 |
|---|---|
| `SwarmConfig/fences.json` | 空域围栏 / 约束参数(缺失时首次运行写默认:不限制) |
| `SwarmConfig/tasks.json` | 多阶段任务状态快照(原子写) |
| `SwarmAudit/session_<会话号>.jsonl` | 每会话审计流水 |
| `SwarmAudit/exports/` | 手动导出的审计副本 |

**任务重启恢复**:软件重启后,重启前 `RUNNING` 的任务一律恢复为 **`PAUSED`(暂停待确认)**,原子写回 `tasks.json` 并反映到任务控制器状态,提示「检测到重启前未完成任务，已暂停，请确认后重新启动」,**不自动续飞**;已完成/中止的任务不会残留。

系统设置(QSettings)另存大模型端点(`SwarmAI/apiBaseUrl`、`SwarmAI/apiKey`、`SwarmAI/modelName`)、自主等级(`Swarm/autonomyLevel`)、L3 白名单(`Swarm/l3AllowedTypes`)等。

## 13. 端到端操作示例

### 示例 A:纯手动一键集群起飞

1. 接入无人机 → 集群面板自动出现。
2. 多机监控区点 **「全选」**(或逐行点选)。
3. 「起飞高度」填 30 → 点 **「解锁」** → 点 **「起飞」** → 确认框选「是」。
4. 需要编队:选队形/长机/间距 → **「开始编队」**。

### 示例 B:AI 自然语言指挥

1. AI 面板点 **「配置」** → 填接口地址/API Key/模型 → **「测试连接」**。
2. 确认自主等级(默认 L2)。
3. 输入框输入 `全体起飞到30米后楔形编队，间距15米` → **「发送」**。
4. 在**计划确认区**逐条审查(必要时「编辑参数」改 JSON)→ **「确认执行」**。

### 示例 C:区域搜索任务

1. 地图中心移到目标区域。
2. 集群面板「区域覆盖任务」填 长/宽/角度/行距 → **「生成并上传」** → **「开始任务」**。
3. 在态势图层观察**覆盖热力**,判断哪片尚未搜索;目标出现时看**目标航迹**图标。

## 14. 注意事项与故障排查

- **面板不显示**:确认已接入至少 1 架无人机(`vehicles.count > 0` 才显示)。
- **AI 无响应 / 测试连接失败**:检查接口地址、API Key、模型名;云端端点需网络可达;不支持工具调用的端点请关闭「Function Calling」。
- **计划被拦截不下发**:多为 error 级约束(超围栏 / 电量不足 / 超链路半径),按提示调整参数或空域配置;或当前为 L1(仅建议,不下发)。
- **某架机不响应集群指令**:很可能它已被操作员在 QGC 手动接管(切到手动模式),集群主动让路;切回自主模式即可恢复纳管。
- **输入被安全过滤拦截**:文本命中防注入模式;改用正常任务描述即可。
- **紧急上锁务必仅在地面使用**:飞行中会导致坠机。

## 15. 已知限制

- **SITL 多机闭环仿真**:PX4/MAVLink L1 已完成 1/4/8 机递进和 6 场景隔离实测；定制 QGC 的
  编队、覆盖、租约与 COP 界面仍需在可交互显示环境按 `sim/SITL测试流程.md` §4 验证。
