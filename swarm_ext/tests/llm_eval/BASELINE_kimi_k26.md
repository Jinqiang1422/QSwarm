## 结论

1. **安全与理解能力已达标**:越界拒绝 100%、歧义追问 100%、态势解读 100%、态势来源标注 92.9%、状态问答 92%。这些是"大模型不直接乱控飞机"的**核心安全红线**,Kimi-K2.6 表现优异——该拒绝的全拒绝、信息不足全追问、态势不编造。
2. **动作类严格准确率低(25%),但主因是"合理补全前置"而非能力不足**:472 条动作类中 55% 是"意图对但补全了 arm/set_selection"(真实无人机起飞确实需先解锁),真错仅 20%。校准后动作类 **80%**。
3. **整体基线**:严格 36.7%;若采纳"补全前置=意图正确"的判定,整体约 **85%**,接近但未达 95% 目标。
4. **异常点**:C 多阶段任务 **0/8**,需专项排查(疑似 `run_task_template` vs `start_swarm_task` 的选择/阶段结构判定,或模板匹配问题)。

## 达标路径(P1 后续,待决策)

- **评测判定校准**:`calls_match` 增加"期望⊆实际"子序列模式(承认合理补全);或评测集 `expected` 补齐前置动作。二者取一,需与系统设计对齐。
- **系统行为对齐**(可选):若定位系统由 `SwarmAIAgent.executeActions` 内部处理解锁,则在 `SYSTEM_PROMPT` + `SwarmAIAgent.cc` 加"精确映射、不补全前置"约束,让模型对齐 `[takeoff]` 期望。
- **降真错**:动作类 20% 真错(尤其 C 多阶段 0%)通过 few-shot / prompt 细化 / 模板匹配修正来压降。
- 达标后重跑回归,验证 intent_accuracy ≥95%。

## 校准后基线(2026-07-22,C 类排查后)

C 类 0/8 专项排查暴露评测判定两个缺陷:
1. **请求超时 120s 不够**:多阶段 `start_swarm_task` 生成很长 stages JSON + 推理链,34 条超时(C 6/8、I、B、D、H 复杂类),记为 `__error__`。已修 `run_eval.py` timeout→300s。
2. **`start_swarm_task` 比 `task_name` 字面相等过严**:E0141/142/147 阶段数完全正确,仅因模型命名"楔形编队巡航返航"≠期望"楔形编队巡航"就判错。
3. **空 `parameter_values:{}` 强制要求键存在**(D 类排查):E0148/157/159 等模型正确引模板、无参数就不输出空字段,却因 `None≠{}` 判错;修正后 D 模板 33%→81%。

用校准判定(补全前置=子序列、`start_swarm_task` 只比阶段数、空参数不强制、剔除超时)对全量已缓存 `actual_calls` 重判(零 API 成本,脚本 `recalc.py`):
