## A. 控制租约(操作员优先 / 逐机让路 / 可恢复 / locale 安全)

**在 QGC 里切某机飞行模式的方法**:FlyView 选中该机 → 飞行模式下拉 → 选目标模式(Position=手动直控,Hold=自主)。或用 MAVLink `SET_MODE`。

### A1 — 接管让路(核心)
- [ ] 前置:8 架在线且未被接管;集群面板可见"已选/在线 8 架"
- [ ] 操作①:对全体下发一次一键指令(如集群面板「返航」或 AI 发"全体返航"),记录反馈架数:`已排队下发至 ___ 架`(应为 **8**)
- [ ] 操作②:把 **2 号机**飞行模式切到 **Position**(手动直控)
- [ ] 操作③:再次对全体下发同一指令
- [ ] 预期:反馈架数变为 **7**(2 号被剔除)
- [ ] 预期:SITL 中 2 号机**不响应**该指令,1、3–8 号正常响应
- [ ] 观察(审计):最新 `session_*.jsonl` 中该次下发的 `action_dispatch` 事件不含 2 号 / 或有接管记录
- [ ] **判定 A1 通过**:架数 8→7 且 2 号不动 ☐

### A2 — 逐机粒度(不误伤其余机)
- [ ] 承接 A1(2 号仍 Position):下发一键指令
- [ ] 预期:**仅 2 号**被跳过;1、3、4、5、6、7、8 号全部执行(逐一在 SITL/QGC 确认各机状态变化)
- [ ] **判定 A2 通过**:只 1 架被隔离、其余 7 架不受影响 ☐

### A3 — 交还恢复(可恢复,非粘滞)
- [ ] 操作:把 2 号机飞行模式切回 **Hold**(或 Mission,均属自主模式集)
- [ ] 操作:再次对全体下发一键指令
- [ ] 预期:反馈架数恢复为 **8**;2 号机**重新响应**下发
- [ ] **判定 A3 通过**:2 号恢复纳管(修复"接管后永不恢复"的粘滞缺陷)☐

### A4 — locale 安全(中文界面同样正确)★本轮修复重点
- [ ] 操作:QGC 设置把界面语言切为**中文**,重启 QGC 重新接入机队
- [ ] 重复 A1(2 号切"定点/Position"手动模式)→ 再切回"等待/Hold"自主模式(A3)
- [ ] 预期:中文界面下让路/恢复行为与英文**完全一致**(2 号让路→架数 7、切回→架数 8)
- [ ] **判定 A4 通过**:判定走固件规范飞行模式访问器、不受语言影响 ☐
      > 反例(旧缺陷):中文下 Hold="等待"曾被误判为接管——若切回 Hold 后 2 号仍不恢复即为回归。

### A5 — 自主过渡模式不误让路(pauseAll→Hold 不自触发)
- [ ] 操作:对全体点「暂停」(集群进入 Hold/悬停)
- [ ] 操作:再对全体下发一键指令
- [ ] 预期:**无一架**因进入 Hold 而被误判接管;反馈架数仍为 **8**
- [ ] **判定 A5 通过**:Hold(pauseFlightMode)属自主集、不触发让路 ☐

### A6 — executeActions 二道守门(AI 路径)
- [ ] 前置:2 号机切 Position(接管);自主等级 L2
- [ ] 操作:AI 发"全体起飞到30米" → 计划确认区「确认执行」
- [ ] 预期:2 号机不被申请租约、不下发;审计 `action_dispatch` 与租约记录不含 2 号
- [ ] **判定 A6 通过**:AI 统一动作管线同样对接管机让路 ☐

## B. 任务持久化(重启不误续飞 / RUNNING→PAUSED / 终结清除 / 容错)

### B1 — 运行态落盘(RUNNING)
- [ ] 操作:经 AI(`start_swarm_task`)或模板库启动一个多阶段任务;确认状态机进入运行、显示阶段推进
- [ ] 观察:`cat tasks.json | python3 -m json.tool`
- [ ] 预期:数组含 1 条记录,`"status": "RUNNING"`,`"id"` = 任务名
- [ ] **判定 B1 通过**:运行态已原子落盘 ☐

### B2 — 重启恢复为 PAUSED(不自动续飞)★核心
- [ ] 前置:B1 任务处于 RUNNING
- [ ] 操作:**强杀 QGC 进程**模拟崩溃:`pkill -x QGroundControl`(注意用 `-x` 精确名,勿用 `-f`)
- [ ] 操作:重新启动 QGC 并接入机队
- [ ] 预期①:出现提示 **「检测到重启前未完成任务「<任务名>」，已暂停，请确认后重新启动」**(AI 面板对话/消息区)
- [ ] 预期②:任务**未自动续飞**(机队不因旧任务自行动作)
- [ ] 预期③:`cat tasks.json` 中该任务 `"status": "PAUSED"`
- [ ] **判定 B2 通过**:三条全满足 ☐

### B3 — 终结任务清除(完成/中止不残留)
- [ ] 操作:启动一个多阶段任务 → 让其正常完成,或点「中止任务」
- [ ] 观察:`cat tasks.json`
- [ ] 预期:内容为 **空数组 `[]`**(终结任务已清除)
- [ ] 操作:重启 QGC
- [ ] 预期:**不出现**任何"未完成任务"提示
- [ ] **判定 B3 通过**:终结任务不误报 ☐
      > 反例(旧缺陷):`_finish` 曾落盘为 PAUSED,导致每次重启误报——若完成后重启仍提示即为回归。

### B4 — 损坏文件容错
- [ ] 操作:QGC 关闭状态下,把 `tasks.json` 内容改成乱码(如 `echo 'not-json' > "$TASKS"`)
- [ ] 操作:启动 QGC
- [ ] 预期:**不崩溃、不报错弹窗**;`loadTasks` 返回空、当作无历史任务处理
- [ ] **判定 B4 通过**:损坏输入被安全吞掉 ☐

### B5 — 原子写不产生半截文件(可选)
- [ ] 说明:落盘用 `QSaveFile`(临时文件 + 原子 rename),掉电/中断不会留下半截 `tasks.json`
- [ ] 操作(尽力):任务运行中反复 `stat "$TASKS"`,确认始终是完整合法 JSON(无 0 字节/截断态)
- [ ] **判定 B5 通过**:未观察到半截文件 ☐
